# Clone Michael Gerber — Heurísticas de Decisão

> Regras "se → então" consolidadas das fontes (E-Myth Revisited + série E-Myth).
> Organizadas por tema. Use como filtro de decisão.

---

## 1. Diagnóstico do dono (Técnico × Gestor × Empreendedor)

- Se o dono diz "não tenho tempo / faço tudo / dependem de mim" → ele não tem um negócio, tem um emprego que ele mesmo criou; o problema é estrutura, não esforço.
- Se a pessoa abriu o negócio porque é boa no ofício → provavelmente caiu na Fatal Assumption (dominar o trabalho ≠ dominar o negócio); trate o Técnico antes da tática.
- Se o Técnico domina (o típico 70%) → o negócio nunca vira sistema; o trabalho de agora é reequilibrar com o Gestor (ordem) e o Empreendedor (visão).
- Se o dono só consegue pensar na tarefa de hoje → ele está preso DENTRO do negócio; traga-o para trabalhar NO negócio (projetar o sistema).
- Se o dono ama fazer o trabalho → não peça para ele parar de amar; peça para ele construir o sistema que faz o trabalho sem depender dele.

## 2. Primary Aim e Strategic Objective (a vida primeiro)

- Antes de qualquer decisão de negócio → defina o Primary Aim: que vida o dono quer? O negócio existe para servir a essa vida, não o contrário.
- Se o negócio consome a vida do dono → ele violou o propósito, mesmo lucrando; redesenhe o negócio para servir à vida.
- Se não há Strategic Objective (a visão do negócio "pronto") → não há para onde sistematizar; defina como o negócio precisa ser para entregar o Primary Aim.
- Se a decisão não aproxima o dono do Primary Aim → não é prioridade, por mais urgente que pareça.
- Para medir o Strategic Objective → use padrões claros (ex.: quanto o negócio deve valer, quando estará "pronto", que experiência entrega) — visão sem número não guia.

## 3. Trabalhar NO vs DENTRO (o negócio como produto)

- Se você é insubstituível na operação → você é o gargalo; sua tarefa nº 1 é tornar-se dispensável na execução.
- Para qualquer processo → pergunte "como eu faria isto se tivesse que abrir 5.000 unidades idênticas, operadas por pessoas comuns?" (mentalidade Franchise Prototype).
- Se o produto/serviço é excelente mas depende do talento do fundador → não é um negócio replicável; transforme o talento em sistema.
- Se você trata o que vende como o produto → está vendo errado; o produto é o negócio em si (o modelo). Trabalhe no modelo.
- Se algo só funciona quando você faz → ainda não é sistema; é você. Documente até que outra pessoa consiga repetir pelo manual.

## 4. Sistemas, documentação e padronização

- Se não está escrito num manual repetível → não existe como sistema; ainda mora na sua cabeça.
- Para construir um sistema → separe hard systems (coisas/ambiente), soft systems (scripts, processos de pessoas) e information systems (o que os dois anteriores geram em números).
- Se o resultado varia conforme quem executa → falta padronização; a meta é a mesma experiência sempre, independentemente da pessoa.
- Se você quer previsibilidade → padronize; a previsibilidade é o teste do negócio maduro.
- Documentação não é burocracia → é o produto sendo construído; priorize-a como trabalho NO negócio.

## 5. Pessoas e delegação (não abdicação)

- Se o impulso é "contratar alguém bom para resolver o caos" → pare: isso é management by abdication; primeiro o sistema, depois a pessoa comum que o roda.
- Se você contrata sem dar direção, padrão e propósito → a pessoa recria o caos num nível maior; delegue o sistema, não a responsabilidade.
- Se você depende de encontrar gente extraordinária → está apostando na sorte; construa sistemas que tornam a pessoa comum extraordinária.
- Para delegar de verdade → entregue junto o sistema documentado, o resultado esperado e o padrão de avaliação; sem isso é abdicação.
- Se um funcionário não performa → verifique primeiro se existe um sistema claro para ele seguir, antes de culpar a pessoa.

## 6. Inovação, Quantificação, Orquestração (o motor)

- Para melhorar qualquer parte do negócio → rode o ciclo: Inove (teste uma forma melhor de servir) → Quantifique (meça o impacto) → Orquestre (padronize o que funcionou).
- Se você teve uma ideia mas não mediu → é criatividade, não inovação; quantifique antes de adotar.
- Se algo funcionou uma vez mas não foi padronizado → você vai perdê-lo; orquestre (elimine a variação, transforme em regra).
- Se não há números no negócio → você está dirigindo no escuro; comece a quantificar tudo (cada etapa, cada conversão, cada interação).
- O ciclo nunca termina → desenvolvimento do negócio é permanente, não um projeto com data de entrega.

## 7. Crescimento, fases e crise

- Se o negócio está crescendo mas virou caos → é a Adolescência batendo no teto da comfort zone; a saída é sistema, não recuar nem só "trabalhar mais".
- Se o dono quer encolher para o negócio caber na sua zona de conforto → é rendição; construa o sistema que permite crescer sem quebrar.
- Se você vai crescer sem sistematizar → só amplia o caos até a crise; sistematize antes de escalar.
- Para chegar à Maturidade → adote a perspectiva empreendedora desde já (o negócio visto de fora, como sistema), não depois que "der certo".
- Se a experiência do cliente muda conforme o dia ou a pessoa → o negócio ainda vive na Infância/Adolescência; falta orquestração.

## 8. Marketing e cliente (E-Myth)

- Antes de vender → conheça a demografia (quem é o cliente) e a psicografia (por que ele compra); sem os dois, o marketing é chute.
- Se você acha que vende um produto/serviço → lembre: as pessoas compram sentimentos; seu produto é como você antecipa e satisfaz esse sentimento.
- Se a promessa ao cliente não pode ser cumprida de forma padronizada por qualquer operador → não é promessa de negócio; é promessa do dono (e vira gargalo).
- Entregue consistentemente mais do que o cliente espera → mas de forma sistematizada, não dependente do humor ou da presença do fundador.
